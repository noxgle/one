How it works

Give it the outcome.
one handles the loop.

The agent takes your goal, breaks it into a plan, uses tools to execute, verifies the result, and reports back. Repeat until done.

G

Goal

You describe the desired outcome in plain terms.

P

Plan

For complex tasks, the agent generates a step-by-step plan.

T

Tools

Reads files, edits code, runs shell commands, searches the web.

E

Execute

Applies changes and runs validation — iteratively.

V

Verify

Tests pass, diffs reviewed, result confirmed.

R

Report

Final summary returned to you — or to CI.

Autonomous execution

Run tasks without a live terminal.

one run executes headless tasks end-to-end. Give it a goal, get back a summary — or structured JSON output for integration with CI pipelines and scripts.

# Autonomous headless task
one run "fix the failing tests"
# Structured JSON output
one run "refactor auth module" --json
{"summary": "Fixed auth session",
  "goalSuccess": true,
  "finished": true}

Stay in control

Autonomy without surrendering control.

Enable cooperation mode to require human approval before any mutating tool executes — bash, write, edit, plan, or apply_patch. In the TUI toggle it with Ctrl+Z, or steer, follow-up, and abort at any time. Autonomous does not mean uncontrolled.

# Headless with cooperation gate
one run "refactor auth" --cooperation
# Write answers to a file for polling
one run "fix tests" --answer-file /tmp/answer.txt --steer-file /tmp/steer.txt
Bring your own model

OpenAI, Anthropic, Gemini, Ollama, llama.cpp, and more.

Connect to any OpenAI-compatible API, or run fully local with Ollama and llama.cpp. Credentials are resolved from runtime input, stored auth, or environment variables. No vendor lock-in.

# Hosted providers
one --provider openai --model gpt-4o-mini
one --provider anthropic --model claude-sonnet-4-20250514
one --provider gemini
# Local models
one --provider ollama --model llama3.2
one --provider llama.cpp --model local

Built for automation

Not just a terminal tool — a programmable agent.

RPC mode for long-lived orchestrator integration, JSON output for machine consumption, task files with parameter substitution, and answer/steer files for human-in-the-loop workflows outside an interactive shell.

# RPC — long-lived integration
echo '{"id":"p1","type":"prompt","message":"test suite"}'
| one --mode rpc
# Task file with parameters
one run @task.txt --param component=auth

Trust & safety

Autonomy with a human in the loop.

Cooperation mode is an approval gate — not a sandbox. You stay in control.

♦ Approval gates

Require human approval before bash, write, edit, plan, and apply_patch tools execute. Toggle with Ctrl+Z in the TUI or use --cooperation in headless mode.

↗ Steering & follow-ups

Guide the agent mid-task with /steer or /follow. Submit follow-up instructions without restarting the session.

▓ Abort controls

Abort any turn with Ctrl+C, reject pending approvals, or use RPC abort channels for programmatic control.

◉ Full visibility

Every tool call, MCP request, and plan step is visible in real-time. Inspect tool results with /details-show. No hidden actions.

⚠ Workspace trust: Extensions and MCP servers are not sandboxed — they run with your permissions. Start one --no-extensions --no-mcp in untrusted repositories. Cooperation mode is an approval gate, not a security boundary.

Install

Get started in seconds.

Install from PyPI or build from source. Requires Python 3.12+.

From PyPI
pip install one-agent
export OPENAI_API_KEY=sk-...
one run "summarize README.md" \
  --provider openai --model gpt-4o-mini
From source
git clone https://github.com/noxgle/one.git
cd one
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
one --help
